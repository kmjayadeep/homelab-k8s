The Swift, Tiel, Qwen3.8 trial, 35B, and vLLM 27B entries use the same **internal accounting rates**, not actual costs charged by either local backend: $0.10/1M uncached input, $0.01/1M cache-read input, and $1.00/1M output. LiteLLM's custom pricing belongs in `model_info`. For OpenAI-style usage with `prompt_tokens_details.cached_tokens`, the intended charge is `(prompt_tokens - cached_tokens) * 0.0000001 + cached_tokens * 0.00000001 + completion_tokens * 0.000001`. Cache reads are counted only if the backend reports cached tokens and the installed LiteLLM version applies the cache rate; metadata or a Model Hub price alone cannot establish actual spend calculation. Verify a repeated benign request's usage and spend record (counts and cost only, no prompt text) after rollout. The 27B entry reuses these existing rates for consistent accounting; they are not a benchmark of operating cost.

To switch the stable alias to another variant, first configure a separate, running backend and LiteLLM `model_list` entry with the correct URL, exact served-model name, pricing (if known), and context limits. Then update only the `qwen-intel` mapping to point at that entry. Do not assume a versioned name remains an accurate pin if its shared backend is repointed. Prefer the Git-managed alias over editing Model Group Alias Settings in the Admin UI, which can create config drift. Verify alias visibility for client keys and a benign request after rollout; Kustomize validation alone cannot prove LiteLLM routing behavior.
