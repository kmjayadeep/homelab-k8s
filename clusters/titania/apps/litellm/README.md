# LiteLLM model names

Use `qwen-intel` in LiteLLM clients that should follow the selected Intel Qwen variant without changing client configuration for each experiment. The local GitOps manifest and the verified database-backed alias select `qwen3.6-35b-a3b-intel`, served by `intel-llama`. The Greatjedi Qwen3.8 MTP trial was applied live on 2026-09-29, then paused after testing; its separate cache and `qwen3.8-27b-intel-test` LiteLLM entry are retained, but that versioned entry is unavailable while its Deployment has zero replicas. After the live-only trial, serving and LiteLLM Flux Kustomizations were left suspended at an older revision; verify the Git source revision and applied state before resuming reconciliation. The versioned `qwen3.6-27b-intel` entry remains pointed at the stopped `intel-vllm` service for a future trial; it is not an alias for the 35B model and is unavailable while vLLM is stopped. Open WebUI connects through LiteLLM and selects `qwen-intel` by default for new chats (individual user defaults can take precedence). The direct `intel-llama` Ingress is not managed anymore; LiteLLM uses internal Kubernetes services.

The retained 27B entry advertises chat, reasoning, and function calling, with 65,536 input plus 16,384 output tokens within its stopped 80K vLLM configuration. One benign `tool_choice: auto` request directly to vLLM returned a structured tool call; test through LiteLLM and with varied workloads before relying on tool quality. The 35B entry retains its existing metadata and 128K limits. The Qwen3.8 trial advertises 114,688 input and 16,384 output tokens within its configured 128K window; tool calling is not advertised until evaluated. It reuses the existing internal accounting rates, not measured operating costs. No vision capability is advertised. Verify the alias and versioned names in the Model Hub after rollout.

The Qwen3.8 trial, 35B, and vLLM 27B entries use the same **internal accounting rates**, not actual costs charged by either local backend: $0.10/1M uncached input, $0.01/1M cache-read input, and $1.00/1M output. LiteLLM's custom pricing belongs in `model_info`. For OpenAI-style usage with `prompt_tokens_details.cached_tokens`, the intended charge is `(prompt_tokens - cached_tokens) * 0.0000001 + cached_tokens * 0.00000001 + completion_tokens * 0.000001`. Cache reads are counted only if the backend reports cached tokens and the installed LiteLLM version applies the cache rate; metadata or a Model Hub price alone cannot establish actual spend calculation. Verify a repeated benign request's usage and spend record (counts and cost only, no prompt text) after rollout. The 27B entry reuses these existing rates for consistent accounting; they are not a benchmark of operating cost.

To switch the stable alias to another variant, first configure a separate, running backend and LiteLLM `model_list` entry with the correct URL, exact served-model name, pricing (if known), and context limits. Then update only the `qwen-intel` mapping to point at that entry. Do not assume a versioned name remains an accurate pin if its shared backend is repointed. Prefer the Git-managed alias over editing Model Group Alias Settings in the Admin UI, which can create config drift. Verify alias visibility for client keys and a benign request after rollout; Kustomize validation alone cannot prove LiteLLM routing behavior. Changes here are GitOps desired state, not proof of a live rollout. The serving manifests retain the pinned Intel AutoRound cache and the Qwen3.6 llama.cpp cache; vLLM remains stopped. The Qwen3.6 A3B llama.cpp Deployment currently owns the B60; for any future Qwen3.8 trial, stop that owner first. Before switching the alias, verify the trial is Ready and test the exact served-model name. The Intel serving and LiteLLM Flux Kustomizations have resumed on the rollback revision; verify their applied revisions and workload readiness after future changes. With `STORE_MODEL_IN_DB=True`, LiteLLM's database-persisted Router Settings can override `router_settings.model_group_alias` from the HelmRelease: after a Helm upgrade to the restored Git alias, the effective alias still pointed to vLLM. It was corrected through authenticated `POST /config/update` with the complete alias map; verify `GET /router/settings`, `/model/info`, and a benign request after any future alias switch. Do not print auth credentials or other config values while checking. Check Git source revision and sole-GPU ownership before resuming each Kustomization. Never enable two B60 GPU inference Deployments at once.
