# LiteLLM model names

Use `qwen-intel` in LiteLLM clients that should follow the selected Intel Qwen variant without changing client configuration for each experiment. The Git-managed `router_settings.model_group_alias` maps that name to the configured `qwen3.6-35b-a3b-intel` model group. The versioned name remains available; both names route to one LiteLLM deployment entry and the same `intel-llama` backend. Open WebUI connects through LiteLLM and selects `qwen-intel` by default for new chats (individual user defaults can take precedence). The direct `intel-llama` Ingress is not managed anymore; LiteLLM still uses the internal Kubernetes service.

To switch the stable alias to another variant, first configure a separate, running backend and LiteLLM `model_list` entry with the correct URL, exact served-model name, pricing (if known), and context limits. Then update only the `qwen-intel` mapping to point at that entry. Do not assume a versioned name remains an accurate pin if its shared backend is repointed. Prefer the Git-managed alias over editing Model Group Alias Settings in the Admin UI, which can create config drift. Verify alias visibility for client keys and a benign request after rollout; Kustomize validation alone cannot prove LiteLLM routing behavior. Changes here are GitOps desired state, not proof of a live rollout.
